## 目录

1. 选择系统的边界
2. 建立全系列历史索引

4. 多路径开放探索
5. 形成有效候选
6. 全历史查重与冷却

## 1. 选择系统的边界

候选池是当天的临时决策记录，不是固定书单。保持：

- **开放探索空间**：古今中外、诗歌、小说、散文、戏剧、书信、日记、自序、访谈、演讲及其他可靠文学文本均可进入搜索。
- **有限决策池**：只把本轮真正核验、比较的候选写入记录。
- **全系列反馈**：从已交付历史中识别原句重复、作者与作品冷却、候选循环和语义饱和。

不得用固定国别配额、随机抽签或“生僻优先”换取表面多样。内容质量优先；发现熟悉路径过密时继续搜索，不把明显较弱的句子强行选中。

## 2. 建立全系列历史索引

每次从零创作前，先从正式交付记录重建索引：

```bash
python3 <skill-dir>/scripts/build_series_index.py \
  --runs-dir <project>/work/daily-quote-runs \
  --out <project>/work/daily-quote-series-index.json
```

索引把 `qa.final_status=passed` 的记录纳入已验收内容历史，与企微是否发送成功分开。同一日期、同一原句、同一作者与作品的视觉改版合并为一张内容卡，但保留全部记录路径；跨日期重复不合并。候选曝光按“日期 + 标准化原句 + 作者”去重，避免同日改版放大统计，并排除正在检查的本轮记录。

历史索引是派生文件，不手工修改。索引缺失、损坏或过期时不得开始生成底图。

schema 1.4 的历史检查自动在本轮 `history/` 保存不可变索引快照，绑定候选文字、作者、作品和索引摘要。换候选必须重新检查；同一个候选 ID 不能继承另一句话的结果。生产锁定及最终放行另核源记录集合是否更新，排除本轮写入；历史回验使用当时快照，不要求它等于今天的全局索引，不能把归档回验当作新交付授权。

## 3. 写当日编辑任务

用户未指定内容时，先看全历史和近期内容，再填写 `editorial_brief`：

- `today_need`：今天希望产生的心理作用和阅读价值。
- `recent_saturation`：近期已经过密的主题、作者圈、体裁或力量来源。
- `underexplored_directions`：系列尚少出现、值得真实探索的方向。
- `avoid_repeating`：今天主动回避的熟悉命题和高频路径。
- `exploration_priority`：准备采用的探索入口，不是预设胜出答案。
- `quality_guardrail`：不为多样性牺牲原文质量、来源和语义完整性。
- `selection_risk`：本轮最可能发生的模型惯性。

用户已指定句子、作者或作品时，记录真实指令；不再用系列缺口否决用户指定内容。

## 4. 多路径开放探索

从零创作不得直接凭记忆列三句名言。至少使用 4 条独立探索路径，且覆盖至少 3 种路径类型。可按任务组合：

- **语义关系路径**：从张力、转折、观看方式或力量来源寻找，不只搜索“励志名句”。
- **体裁来源路径**：进入近期较少使用的小说段落、戏剧对白、书信、日记、随笔、访谈等原始来源。
- **时代文化路径**：到不同年代或文化中寻找相容但表达机制不同的文本。
- **具体作品路径**：从完整作品或权威文本页向内阅读，不从语录聚合页反向找出处。
- **偶遇路径**：允许从可靠文学机构、出版社、图书馆目录或作品选段发现非预设作者。

把每条路径写入 `discovery_routes`，包括搜索意图、范围、初步线索数、进入有效池的候选和实际发现。所有路径合计至少检查 12 条初步线索。

`route_type` 使用稳定一级值 `semantic/genre/culture_period/primary_work/serendipity`，具体范围自由描述。每条路线的 `leads` 保存实际查看的线索：`locator` 和一句 `observation`（发现或淘汰理由），`raw_count` 必须等于线索条数。不要拿多个查询词或同一语录页的不同标签当独立探索；没有实际探索时补查，不补写虚构证据。

这些数字是防止过早停止的过程下限，不是固定作者、年代或国别配额。

## 5. 形成有效候选

开放选句至少保留 5 条有效候选，且有效候选作者不得重复、来源类型至少 3 种、结构化语义签名至少 3 种。有效候选必须：

- 能定位到具体作品、访谈或明确来源线索。
- 脱离上下文后不反转原意。
- 单独阅读仍有思想或情绪价值。
- 不是只靠作者名气成立的口号。
- 长度和节奏有机会适配日签。
- 至少存在一种非字面视觉关系。

有效池仅包含 `source_status=locatable` 或 `verified` 的候选，胜出项必须 `verified`。每条有效候选保存 `source_locator` 与 `source_note`：

```json
{"source_locator":{"url":"https://原文页","local_path":"","location":"篇章或段落"},"source_note":"页面内哪段文字支持摘句及语境"}
```

URL 与本地文件二选一；本地使用绝对路径且必须给页码／段落等 `location`。仅来源页面明确可定位的候选才计入有效池，不将 rejected/unverified 凑入数量。译文候选还须有 `translator` 与 `edition`，胜出项与 `content` 一致。

每条候选记录：`work`、`source_type`、`cultural_context`、`period`、`discovery_route_id`、`semantic_signature`、`novelty_note`。这些字段用于观察系列分布，不用于机械规定国别或年代配额。`semantic_signature` 至少包含：

- `desired_effect`
- `core_tension`
- `source_of_strength`
- `emotional_temperature`

不要用换标签的方式伪造语义差异。若五条都在说“熬过去”，即使作者不同也继续扩展。

`source_type` 一级值使用 `poetry/prose/fiction/drama/letter/diary/preface/interview/speech/literary_criticism/other`；“古诗、现代诗、英语诗”都属于 poetry，文化年代另记。一级表只统一统计，不是封闭文学范围，其他真实来源可用 other 并说明。

`content_selection.semantic_diversity_review` 写 `decision` 和 `note`：引用至少三条候选的实际关系比较，说明差异在哪里；同义词、序号和作者不同都不算语义差异。这个判断由阅读者负责，脚本只核合同，不将字符串不同宣称为语义已被证明。

## 6. 全历史查重与冷却

完成候选池和暂定胜出项后运行：

```bash
python3 <skill-dir>/scripts/check_quote_history.py \
  <run>/design-record.json \
  --history-index <project>/work/daily-quote-series-index.json
```

脚本会把标点、空白、Unicode 形式等标准化后检查完全重复，并用序列相似度识别近似版本；显示原文绝不因查重而改写。

处理规则：

- 完全重复：`open_search` 硬性淘汰。
- 高度近似、仅增删少数字词：`open_search` 默认淘汰。
- 同一作者 21 天内再次出现：软冷却，继续扩展；确有内容优势时写明理由后可通过。
- 同一作品 60 天内再次出现：软冷却，继续扩展；确有内容优势时写明理由后可通过。
- 某候选在 60 天内至少 3 次进入候选池：进入软审查；继续扩展，确有优势时填写 `candidate_exposure_decision=justified` 与具体理由后重新检查。

作者／作品冷却只计算不晚于本卡日期的历史，不能让未来卡片遮住近期使用；未来同句仍须提示重复。候选曝光阈值按排除本轮后的历史计，不因重建索引是否含当前文件而变化。

脚本出现 `failed` 或 `review_required` 时不得锁定。冷却项确有充分理由时填写 `cooldown_decision=justified` 和具体 `cooldown_rationale`，重新运行脚本。

历史检查通过后运行：

```bash
python3 <skill-dir>/scripts/validate_selection.py \
  <run>/design-record.json
```

只有 `SELECTION VALIDATION PASSED` 才结束选题阶段。不要用临时人工检查代替这个确定性闸门。

## 7. 核验、比较与决选

先过硬门槛，再做编辑比较。

硬门槛：

- 全历史查重通过。
- 来源、版本和上下文可核。
- 原句未被拼接、修补或误署名。
- 译文绑定明确译者与版本。
- 摘要没有冒充作者原话。
- 暂定胜出作者已按内容诚信参考完成背景核查，`author_review.decision=pass`；它是使用适宜性判断，不替代原句核验。换人后重新核查，不为全部初步线索做人物调查。

比较维度：

| 维度 | 核心问题 |
|---|---|
| 当日编辑价值 | 是否真正回应今天，而非重复系列惯性？ |
| 思想密度 | 短句中是否有真实张力、限度或余味？ |
| 情绪真实性 | 是安慰、清醒或力量，还是强迫积极？ |
| 系列新鲜度 | 作者、作品、体裁、力量来源和核心关系是否有新信息？ |
| 视觉潜力 | 能否转译为关系、节奏或材质，而非直画名词？ |
| 排版适配 | 长度、标点和节奏是否能形成清楚层级？ |

评分只辅助比较。若新鲜候选明显较弱，不为追求多样性强行选中；继续搜索，直到出现质量相当且系列价值更高的候选。

至少把胜出项与一条质量接近、核心关系不同的次优项写入 `content_selection.finalist_comparison`，分别说明内容质量、核心关系及相对胜负。不得只写胜出项的优点。

## 8. 动态停止条件

从零创作只有同时满足以下条件才能停止：

1. 至少 4 条探索路径、3 种路径类型、12 条初步线索。
2. 至少 5 条来源可定位的有效候选。
3. 有效候选作者不重复，来源类型至少 3 种。
4. 至少有 3 种真实不同的语义签名。
5. 暂定胜出项通过全历史查重、来源核验和作者使用适宜性核查。
6. 至少两条终选候选内容质量接近但核心关系不同。
7. 胜出理由、次优差异、风险和停止扩展理由均可说明。
8. 继续扩展的预期收益确实较低。

达到数量下限但仍集中于熟悉作者圈、常见名句或同一精神母题时，不得停止。

## 9. 指定内容与复用例外

`user_supplied` 和 `revision` 允许单候选，不要求多路径搜索，但仍必须核验原文并运行全历史检查。

只有用户明确要求复用同一句或对同一句换设计时，才允许：

- 把模式设为 `user_supplied` 或 `revision`。
- 设置 `history_dedup.reuse_authorized=true`。
- 逐字记录 `reuse_authorization_reason`。
- 重新运行历史检查，取得 `passed_with_user_override`。

模型不得自行授权复用。没有明确用户指令时，跨日期开放选句一律不允许重复。

## 10. 记录要求与失败信号

生成前记录必须包含：

- 全系列历史索引路径、构建时间、扫描数量与哈希。
- 当日编辑任务。
- 真实探索路径和初步线索数。
- 至少 5 条有效候选及结构化语义签名。
- 每条候选的历史检查结果。
- 暂定胜出项的重复、冷却和候选曝光情况。
- 决选理由、次优差异和停止扩展理由。
- `content_selection.author_review` 的身份、检索范围、证据、判断与局限；被换掉作者的调查随对应候选保留，不将未证实指控记成事实。

失败信号：

- 先凭记忆写出几个熟悉作者，再补“开放搜索”说明。
- 刚达到最低候选数就停止。
- 候选作者不同，但表达同一种“坚持、接受、熬过去”。
- 多条探索路径实际使用同一批语录站或同一作者圈。
- 查重只看最近 3–5 张，不查全历史。
- 用改标点、删字或流行改写规避重复检测。
- 为多样性选择明显较弱、来源更差的文本。
- `review_required` 尚未处理就开始生成底图。
